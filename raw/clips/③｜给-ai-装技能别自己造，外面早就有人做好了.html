开篇：你为什么能在电脑前工作，而不是去搬砖

先给 Skill 一个特别朴素的定义。

你之所以能坐在电脑前工作、别人得去打螺丝，是因为你过去学习和工作里 攒了一些技能 ，你会干这个事，别人不会。

Skill 就是把这个”你会干的事”，变成 AI 也会干。

公司里所有 稳定在重复做的事 ，理论上都可以变成 Skill：

  • 业务员找客户
  • 运营维护网站
  • 运营维护社媒
  • 运营投广告
  • 销售跟进客户
  • 老板看跟进情况、看消耗、看 ROI

这些全都是 Skill。

所以当你装好一个 Agent，它其实只是个”会听你说话的壳”。 它会不会干活、能干多少种活，完全取决于你给它装了什么 Skill。

一、第一个反常识：千万别自己写 Skill

我知道这听起来很奇怪——“把我们公司的方法固化下来，不正是 Skill 的意义吗？”

对，但顺序错了。

Agent 确实可以自己创建 Skill。你只要说一句：“我要做一个运营网站的 Skill，我的思路是一二三，帮我做出来。“它就能给你生成一个。

但我的建议是： 除非你非常确定这件事特殊到全世界只有你在做，否则别自己造。

为什么？三个理由：

1. 互联网的底子早就搭好了。

你想做的事，大概率已经有人做过，而且做得比你好。

2. 开源生态是白给的。

程序员世界有个奇特的文化：把代码无偿分享出来，你随便用，还能商用。

3. 自己造的 Skill 要养，而多数人养不起。

Skill 不是写完就完事，它要在用的时候不断纠错、进化。这是一笔持续的账。

那我自己公司的方法论怎么办？

我的做法是这样的：

  1. 摸索期
    ：大量装别人的 Skill，让它自己去跑、自己去识别哪些有用哪些没用。
  2. 收敛期
    ：跑通之后，让它”反思总结一下”，输出一个 MD 说明文件。你自己过一遍，确认没问题。
  3. 固定期
    ：以后就让它按你这份 MD 跑。那些装了但没用的 Skill，它自然就不会调用了。

所以真正的路径是：先用别人的，跑通了，再沉淀成自己的。

而不是一上来自己写。

二、去哪找：三个地方，各有分工

1. GitHub —— 质量最高，首选

GitHub 是程序员放代码的地方，上面有海量 Skill。

怎么挑？看两个数：

  • 星标（Star）
    ：就像大众点评。你到一个地方找吃的，自己瞎撞大概率踩坑；看评分高的，基本不会错。星标高意味着”已经被别人筛过一遍了”。
  • 开源协议
    ：看到 MIT 协议 ，基本可以放心用，没有任何风险。

⚠️ 知识产权这条线，做外贸的要格外注意。

我们最怕的是：东西用到一半，突然来个侵权通知。线上被下架还好， 线下的货已经铺出去了，你怎么收回来？ 国外在这块管得很严。所以看到 MIT 协议，你至少不用提这个心。

我自己用得最多的一个，是 Marketing Skill。 名字听着泛，但国外的”marketing”约等于我们说的”外贸营销”——独立站、社媒、内容、转化，全在里面。它里面按功能分了：CRO（转化率优化）、写作、SEO、分析、增长引擎……基本你日常营销要用的能力，它都有。

2. ClawHub —— 龙虾生态的沉淀

龙虾火了一阵，虽然产品本身没被大量使用，但它留下了很多 Skill。这个生态里的东西不如 GitHub 那么”被程序员筛选过”，但有不少是针对具体场景的现成方案。

（顺带一提：国内产品里很多 Skill，是从这个生态里搬回来本地化的。）

3. Agent 自带的连接器 / 技能市场

各家 Agent 都有自己的技能市场，比如 WorkBuddy 里的「专家技能连接器」。里面有招聘专家、销售教练，甚至还有”赛博神算子”——现场我随手输了个生辰八字让它算，还真给算出来了，四柱排盘、大运流年一套一套的。

这个例子其实说明一件事： Skill 的想象力远比你以为的大。

怎么装？

简单到离谱。你在上面看到地址，复制，然后告诉你的 Agent：

帮我把这个 Skill 装上。

它自己就下载、自己装、自己维护。装在电脑哪个目录你都不用关心，它自己找得到。

⚠️ 一个小技巧： 如果你用多个 Agent，把它们授权到同一个目录。 比如都授权到 project 目录——这样 A 装的 Skill，B 也能用，反之亦然。

要用的时候不用你指定。 你装了，它自己会判断该调哪个。当然你不放心，也可以明示：“用某某 Skill 帮我干这个”，这样能省掉它的思考过程。

三、Skill 的真正作用：省钱

这句话我在现场说了，很多人没反应过来。

Skill 是帮你省 token 钱的。

原理是这样的：Agent 每说一句话、每思考一步，都花钱。你不给它约束，它会自己放开想——而”想”这个动作，是非常贵的。

Skill 相当于给它一条已经验证过的思考路径： 这个活，按这五步走，别自己瞎琢磨。

路径越清楚，废动作越少，钱花得越少。

你可以把 AI 的思考想象成水和电——如果资源无限，任何事都能干。但过日子都得算账。 Skill 就是把”无限思考”变成”按需思考”的开关。

所以摸索期你尽管多装、让它随便跑；一旦跑通，一定要 收敛成一份固定的说明文件 。这一步省下的钱，比你在订阅档位上纠结管用得多。

四、进阶：怎么把老员工的经验”炼”成 Skill

好，现在说那个你可能真正关心的问题： 我公司里那些只有老员工会的东西，怎么办？

（先说一句实话：你防也防不住。外贸这套东西，不需要从你员工身上炼，别人早就炼好了，AI 已经会了。）

方法是这样的：

第一步：录下来

我手上常戴了个手表，一百来块钱，只有一个功能：录音。我只要在外面说话就开着它。

为什么用这么简陋的东西？因为 所有分析我都是用自己的 Agent 做的 。

用别人的分析工具，它没有我的知识库——我说个”WhatsApp”、说个”询盘云”，它识别得乱七八糟（我这鼻音确实重）。而我用自己那个 Agent，它知道我的习惯、知道我过去的语境、知道我的知识库里有什么。

所以我只需要它录音，剩下的交给 Agent。

⚠️ 同样的逻辑适用于你们： 在公司开个固定会议室，一直录。 只要有人说话就录，录完过 AI，全部数据化。这样你公司线下的很多行为，AI 就能读懂了。

我们公司现在所有远程会议都用企业版腾讯会议，因为它能自动出纪要。纪要出来之后接上 Agent，我直接说一句”这是客户开会记录，帮我在系统里把客户提的问题都记一下”——它就自动记进去了。

第二步：让它学

把录音/文字扔给它：

这是我们讨论 XX 工作的录音，你去学一下这件事是怎么做的，做成一个 Skill。

第三步：用中纠错

Skill 装上之后不是终点。用一段时间，让它自己复盘：

你跑一下昨天的那些任务，看看有没有说得不对、做得不好的地方，自己去优化一下。

它会自己进化。

我在 WhatsApp 客服上就是这么干的（第 10 篇详写）：每天让更强的模型去读昨天的客户对话，找出话术有问题的地方，自己改。大概四五天之后，基本就不用管了。

一个前提：这一步值得做吗？

我的判断标准很简单：

只有你判断这件事”非常非常特殊”的时候，才值得自己造 Skill。

否则，去 GitHub 找。

五、附赠：建站类 Skill 的清单（这类 Skill 数量最多）

Skill 里数量最多的一类，是网站相关的。我在现场攒了一批，按三类给你：

设计类

  • 设计品味（解决”一眼假”——AI 做的东西很多人一眼能看出来）
  • UI/UX 模板库
  • 配色规范（比如你 logo 是橙色，相关配色就都得跟橙色搭，别突然来个大红大绿）
  • 前端布局
  • 高级感打磨（摄影风格、苹果风格、精细排版）
  • 动效库（进网站看到的各种动态效果）
  • UI 组件库（按钮、卡片这些已经组件化的东西）

转化类 （这个才是重点——网站不是做出来就完了，是要带来客户的）

  • 表单设计
  • 落地页设计
  • 信任元素（怎么表达更容易被信任）
  • 文案说服力
  • Offer 设计（赠品、保证、限时这类）
  • 弹窗设计
  • 注册与转化路径
  • A/B Test

内容与技术类

  • SEO 规范（EEAT）
  • 社媒文案（Facebook 帖怎么写、小红书图文怎么做）
  • 图片生成接口调用

⚠️ 现场演示：同样一个 PDF， 加 Skill 之前和之后，做出来的网站完全不一样 。

加之前：一个 page，点”立即咨询”会跳到别的地方去。

加之后：配色像样了，表单留在页面上了，转化路径通了。

而这还只是”及格”。 真正能用的网站，还得靠知识库——那是第 4 篇和第 7 篇的事。

本篇清单

  • Skill = 把你公司稳定在重复做的事，变成 AI 的能力
  • 路径： 先用别人的 → 跑通 → 收敛成自己的 MD → 按 MD 跑
  • 找 Skill：GitHub 看 星标 + MIT 协议 ；ClawHub；Agent 自带市场
  • 装 Skill：把地址丢给 Agent 就行；多个 Agent 授权到 同一目录 可共用
  • Skill 的本质价值是 省钱 （约束思考路径，减少废动作）
  • 自己造 Skill 的唯一理由： 这件事特殊到外面没有
  • 造 Skill 的方法：录音 → 让 Agent 学 → 用中纠错 → 自动进化
  • ⚠️ 用别人的代码前先看协议，MIT 基本无风险

04｜知识库：AI 时代公司最值钱的资产，为什么必须在你自己手里

Skill 是别人的，知识库是你自己的。
