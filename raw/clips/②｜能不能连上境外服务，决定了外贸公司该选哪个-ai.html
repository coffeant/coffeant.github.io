开篇：为什么外贸人不能只看”国内还是国外”

先说一个判断，可能会得罪人：

如果你做的是外贸，纯国内产品在”最后一公里”上会卡。

原因不是国产模型不好——最近几个月国产开源模型的进步速度，说实话有点集中爆发的意思，Kimi、DeepSeek、通义、GLM 都在快速迭代，DeepSeek 新版本连视觉能力都补上了。

问题在于三个现实：

  1. 合规约束。
    国内产品必须遵守国内法律。你让它去查 Google 的什么、Facebook 的什么，它是受限制的。
  2. 默认模型。
    国内产品默认集成的是国内模型。
  3. 训练语料。
    而我们要大量生成的是英文内容、是要发给客户看的东西。AI 的能力来自它读过什么——它读的英文世界的东西，和它读的中文互联网的东西，是两片不同的海。

所以从逻辑上推： 做外贸、生成英文、跟境外客户打交道，用境外的工具会顺一些。

但我马上要说另一面——

一、一个被严重低估的障碍：联网

我在现场问过很多程序员群体一个问题：你能不能稳定访问境外的开发者服务？

底下坐着的是各公司的 CTO、架构师、资深开发。 举手的人寥寥无几。

（这里只讨论”能不能访问”这个客观事实。具体怎么解决，请各位遵守所在地区的法律法规和公司的 IT 合规要求，本文不展开。）

他们想用 Claude，用不了。原因就这么简单。

这件事看起来特别基础，但 它真的卡住了非常多人 。尤其是”新手外贸”——很多刚入行的业务员，第一个障碍不是不会写开发信，是根本连不上。

所以我的第一个结论非常明确：

如果你连稳定的境外网络访问都没有， 别挣扎了，直接选国内产品。

目前这个位置上，腾讯的 WorkBuddy 是零障碍的：搜一下、下载、装、用。它背后接的是国内模型，中文场景、公司内部事务（行政、财务、文档）都能干。

先把 AI 用起来，比用什么 AI 重要一百倍。

二、三个选项的真实取舍

选项 A：Claude Code —— 能力天花板最高，但你可能活不过三个月

Claude Code 是最早做这类产品的，最早是给程序员用的。所以现在还在用 Claude Code 的人，通常是两类：技术底子不错，或者运气很好。

运气很好指的是：它封号封得很凶。

今年五六月那波封号，我们公司程序员几乎全军覆没——原来人手一个，后面基本都没了。最严重的是杭州周边，道理也不复杂：DeepSeek 在那儿、阿里在那儿，同一个 IP 段每天不停访问 Claude 的接口，对面一判断地址就知道这些不是真实用户。

我自己那个号还活着。我对比了很久，最可能的原因是： 我跑的任务大量是英文任务，其他同事跑的基本都是中文任务。

这只是推测（现场口径）。但如果你问”怎么才能不被封”，除了环境、时区、系统语言、IP 稳定性这些老生常谈之外，我给不出确定答案。

结论：如果你有技术信心、有稳定环境、能接受某天醒来号没了，Claude Code 的能力上限确实很高。否则别把它当生产工具。

选项 B：Codex —— 大多数人应该无脑选这个

Codex 是接 ChatGPT 的。有个数据很能说明问题（现场口径，未经第三方核实）：

Codex 上线之后，ChatGPT 发现 96% 的 token 消耗都跑到了 Codex 里面 。网页版推了三年，Codex 上线几天就把用户吸走了。

用户是用脚投票的。

你一旦用过”它直接把活干完”的体验，就回不去”它告诉你怎么做、你自己动手”的体验了。

另外，Codex 的迁移成本也是几个产品里相对可控的。而 agent 这类产品迁移起来其实很痛苦——它有记忆、有工作习惯、有你的 skill 和 memory，不是重装一下就完事。

我的建议是：如果你没有特别的判断和偏好，就选 Codex。

选项 C：WorkBuddy —— 国内零障碍，且是”公司级”的更优解

前面说了，网络障碍者的第一选择。

但我想多说一层： 腾讯在这个位置上，走的是”公司级”路线。

为什么这点重要？前面讲过：Codex、Claude Code 都是 安装版 。装在我电脑上，你用不了。结果就是——你昨天刚写过的东西我不知道，我又写一遍， token 双倍消耗 。

这是个隐性成本，很多老板没算过。

企业要用，就得是所有人访问同一个东西。这需要的是 服务器版 / 网页版 ，而不是每人装一个客户端。

这是目前整个领域正在解决、但还没解决好的问题（第 4 篇会讲知识库怎么共用）。

关于阿里 Accio-Work

如果你公司深度依赖阿里国际站，它会给你一些现成的便利。但我个人建议 谨慎 ——

理由很简单：来听这个课的人，多半是想 脱离单一平台、自己做点别的 的。如果你不想被绑定，尽量别入坑一个天然绑定在某个平台上的工具。何况从产品热度和迭代速度看，它和前面几个还差着一个量级。

而且，agent 一旦用上，迁移难度极高。 选的时候要谨慎，因为换的时候会很疼。

三、装上之后，你一定会遇到的三件事

1. 环境依赖提示：别慌，那就是它自己

Codex 跑在 Node 环境里。所以安装时如果你的电脑没装过 Node，它会提示你装。 安装过程中弹出「Node 要访问某某」的时候，你要知道那就是 Codex 在访问。

Claude Code 依赖的是 Git，安装要跑挺久，耐心等它装完就行。

2. 付费门槛：这是真实存在的，但解决方案不止一种

境外工具升级订阅，通常需要境外支付方式，这对大部分人是真实障碍。常见的思路有三类：

  • 正规路径
    ：通过合规的境外支付渠道自行完成（如境外发行的支付方式、公司统一申请的商务卡等）。替代方案是通过苹果手机余额来升级 ChatGPT 的方式，不懂的加我微 jiadingqiang 沟通。
  • 替代路径
    ：通过 cc-Switch 改用国内模型的 API。多数客户端都支持自定义模型服务地址，按各家官方文档配置即可——好处是额度焦虑没了，成本可控；代价是能力会下降一档。
  • 削峰填谷
    ：很多国内模型 API 是分时段计价的，非工作时段便宜（现场口径）。外贸人有个天然优势—— 你的客户在你睡觉的时候上班 。把批量任务排到晚上和周末跑，成本能下来一截。

3. 中转站：我劝你别碰

说到省钱，一定会有人想到中转站。我把风险摆清楚，你自己判断：

风险一：明文。

你的 agent 要干活，就得知道一堆账号密码——邮箱的、WhatsApp 的、各种平台的。中转站是个通道，它过去的时候如果留一份，你的账号密码就全在别人手上。

而且这种损失你感受不到。就像银行账户每天少一毛钱，你根本查不出来。

风险二：以次充好。

为什么能便宜？因为它标着是 A 模型，背后跑的其实是便宜得多的 B 模型。你能分辨出来吗？大多数人分不出来——AI 自动干活的时候，那个差别小到你不会注意。

风险三：订阅转售。

有人把整包订阅拆成 API 卖给你。Token 没变、质量没变，但原本不限速的 API 变成了一群人挤一个限速套餐。你还是感受不到，因为你不知道正常速度该是多快。

如果非要用，我只能说： 尽量选规模大、信息透明、有明确服务条款的平台 。那些”性价比高到离谱”的小中转站，风险你自己扛。

中转站唯一真实的好处是：一个账号能用很多模型，不同任务用不同模型省钱——简单任务用免费模型，复杂任务用 DeepSeek，最难的才上 Claude。

这个思路本身是对的，但请走合规渠道。

四、成本：你会经历的三个阶段

阶段一：订阅。

大部分人开始都选订阅，因为用 API 你心里没底，账单会吓到自己。常见的是两档：20 美金和 120 美金（现场口径）。

我的观察： 运营选 20，老板选 120。

阶段二：额度焦虑。

额度一般几小时重置一次。你会变成这样：额度没了——去把发票贴一下；额度还没恢复——去把办公室卫生打扫一下；早上一睁眼——赶紧跑，别把这几个小时浪费了。

这不是段子，这是真实状态。

阶段三：认清现实。

跑了一阵，任务越来越多，你会发现它没那么神。这时候你才真正理解 AI 能干什么、不能干什么。

这个阶段才是值钱的。

五、一个反直觉的建议：先用起来，别先优化

我在现场演示了怎么用语音输入跟 AI 说话——说完它自己就输进去了，基本不用改。

有人说”我怎么老出错”。我的体感是几乎不出错，开车的时候都能直接说、不看就发。

差别在哪？大概是我日常在抖音发短视频，说的都是那些话，它学了我的语境。

这就是这类工具的本质：你的上限，取决于你喂给它多少。

所以别在工具选择上花太多时间。选一个、装上、用起来、把你的东西喂进去。

三个月后你的收获，一定大于你今天研究选型一个月的收获。

本篇清单

  • 决策树
    ：连不上境外服务 → 选国内产品（WorkBuddy）；能连上、没特殊偏好 → Codex；有技术信心、能承受封号 → Claude Code
  • 公司统一使用时， 优先考虑网页版/服务器版 ，避免每人一个客户端导致的重复消耗
  • 安装提示 Node = Codex ， Git = Claude Code
  • ⚠️ 中转站：明文存账号密码 / 以次充好 / 订阅转售限速 —— 三条风险，非必要不碰
  • 省钱的正确姿势： 分任务用不同模型 + 把批量任务排到非高峰时段
  • 别在上瘾期做采购决策
